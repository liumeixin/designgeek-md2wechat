## 二、逐项复核（以 ugreen 导出为证据）

### 2.1 表格 `<table>`

| 检查项 | 结果 |
|---|---|
| 标签支持 | ✅ `table/thead/tbody/tr/th/td` 均在公众号白名单 |
| `§1.4` 固定宽度 | ✅ 导出**不含** `width`，不存在固定宽度 |
| `§4.1.1` 对比度 | ✅ `th` `rgb(137,240,168)` on `rgb(21,26,22)` = **12.67:1**；`td` `#30352f` on 白/`#f0f4f0` ≈ **12.5:1** |
| 单元格边框 | ✅ 每个 `td/th` 都内联了 `border:1px solid rgb(207,214,207)` |
| ⚠️ `border-collapse` | **丢失** —— 主题写了 `border-collapse: collapse`，导出后 `<table>` 上没有 |

导出实测：

```html
<table style="color:rgb(48,53,47);font-size:16px;font-weight:400;font-style:normal;
              text-align:left;list-style-type:disc;">
```

> 主题原文：`#wenyan table { border-collapse: collapse; margin: 1.2em auto; width: 100%; }`
> 三项里 **`border-collapse` / `width` / `margin` 全部没进导出**。

### 2.2 引用块 `<blockquote>`

| 检查项 | 结果 |
|---|---|
| 标签支持 | ✅ `blockquote` 支持 |
| `§4.1.1` 对比度 | ✅ `rgb(82,96,85)` on `rgb(238,244,238)` = **5.95:1** |
| 左边框 / 底色 | ✅ `border-left:3px solid rgb(31,212,95)`、`background-color` 均内联 |
| ⚠️ `padding` / `line-height` / `margin` | **丢失** —— 主题写了 `padding:16px 18px; line-height:1.85; margin:1.2em 0` |

导出实测：

```html
<blockquote style="color:rgb(82,96,85);font-size:14px;font-weight:400;font-style:normal;
                   text-align:left;background-color:rgb(238,244,238);
                   border-left:3px solid rgb(31,212,95);list-style-type:disc;">
```

> 后果：文字会**紧贴** 3px 绿色左边框（预览里有 18px 内边距）。
> `border-radius:0` 已被 no-op 表正确丢弃，符合预期。

### 2.3 行内代码 `<code>`

| 检查项 | 结果 |
|---|---|
| `§4.1.1` 对比度 | ✅ `rgb(18,128,58)` on `rgb(238,244,238)` = **4.51:1**（刚过线） |
| `§3` font-family | ⚠️ 内联了等宽字体栈 —— **脚本豁免**（`code/pre/kbd/samp`），报告亦记为「功能性例外」 |
| 底色 / 圆角 | ✅ `background-color`、`border-radius:3px` 均内联 |
| ⚠️ `padding` | **丢失** —— 主题写了 `padding:2px 6px`，导出后没有 |

### 2.4 代码块 `<pre>` / `<pre><code>`

| 检查项 | 结果 |
|---|---|
| `§1.8` `<pre>` 必须含 `<code>` | ✅ 导出为 `<pre><code class="language-bash">…</code></pre>` |
| `§4.1.1` 对比度 | ✅ `pre>code` `rgb(238,242,237)` on `rgb(21,26,22)` = **15.58:1** |
| 底色 / 边框 / 圆角 | ✅ 均内联 |
| ⚠️ `white-space` / `overflow-x` / `display` | **丢失** —— 主题写了 `#wenyan pre code { display:block; overflow-x:auto; }` |
| ⚠️ `padding` / `margin` / `line-height` | **丢失** —— 主题写了 `padding:16px`、`line-height:1.6` |

> 后果：**长代码行没有换行/滚动兜底**。`<pre>` 的浏览器默认是 `white-space: pre`（不换行），
> 主题本意用 `pre code { overflow-x: auto }` 让长行可横向滚动，但这条没能进导出。
> 移动端窄屏下，超长行有溢出/被裁的风险。
>
> 参照：本项目**自己的小红书分页路径**（`index.html` 的 `splitContentIntoPages()`）就特意补了
> `#wenyan pre { white-space:pre-wrap !important; word-break:break-all !important; }` ——
> 说明作者清楚这条是必需的，但**公众号导出路径没带**。

## 三、3 处保真缺口（根因）

根因是同一个：`frontend/index.html` 的 `copyHtml()` 里 `copyProps` 白名单
**故意排除**了 `display / width / height / overflow / line-height / margin / padding`，
注释理由是「公众号编辑器会自己处理布局，内联这些会导致文字重叠」。

| # | 缺口 | 影响的属性 | 后果 | 严重度 |
|---|---|---|---|---|
| 1 | `<table>` 无 `border-collapse` | `border-collapse` | 若微信端不自行补上，相邻单元格边框走**分离模型** → 视觉上 2px 双线 | 中 |
| 2 | `<pre>`/`<code>` 无换行兜底 | `white-space` / `overflow-x` | 长代码行溢出或截断 | **高** |
| 3 | 引用块 / 行内代码 / 代码块无内边距 | `padding` | 引用文字贴边框；行内代码底色贴字；代码块文字贴边 | 中 |

> ⚠️ 缺口 2 与规范 §1.8 的立法意图同源 —— §1.8 说「`<pre>` 包普通文本会被截断」，
> 我们靠 `<code>` 满足了它的**字面要求**，但**换行兜底**这一层没做。

## 四、2 类冗余（体积 / 可维护性）

实测（ugreen 导出 9 462 B）：

| 项 | 出现次数 | 说明 |
|---|---|---|
| `list-style-type:…` | **40** | 被内联到 `table/th/td/h1/p/pre/code/hr` 等**所有**元素上，但只对 `ul/ol/li` 有意义 |
| `border-left/top/right/bottom` | **55** | 与 `border` 简写完全重复（每个单元格 5 条边框声明） |

> 两者合计约 2.5 KB / 9.5 KB ≈ **26%** 的体积。删除**不影响任何视觉**。
> （`border-color / border-style / border-left-color` 三个更冗余的长写此前已移除，
> 但 `border-<方向>` 这四条简写还留着。）

## 六、建议

| 优先级 | 动作 | 影响面 |
|---|---|---|
| P0 | 给 `copyProps` 补 `white-space`（配 no-op 规则丢掉 `normal`），解决长代码行溢出 | 全主题，仅代码块生效 |
| P1 | 给 `copyProps` 补 `border-collapse`（配 no-op 丢 `separate`） | 全主题，仅表格生效 |
| P2 | 对 `blockquote` / `pre` / `code` **定向**补 `padding`（不做全局 padding，避免动正文间距） | 三类元素 |
| P3 | 清理 `list-style-type`（仅保留 ul/ol/li）与冗余 `border-<方向>` | 全主题，省 ~26% 体积 |

> P0–P2 属「让主题声明的样式真正生效」，**不改主题设计**；
> P3 属纯瘦身，**零视觉影响**。四者都改 `copyHtml()` 一个函数，可一起做。

## 八、修复记录（2026-10-12，已实施）

改动**只集中在 `frontend/index.html` 的 `copyHtml()` 一个函数**，主题 CSS 与 `themes.json` 未动。

### 8.1 改动内容

| # | 位置 | 改动 |
|---|---|---|
| P0 | `NOOP_RULES` / 元素循环 | 新增 `isCodeBlock()`：对 `<pre>` 及其内部 `<code>` **定向**补 `overflow-x:auto`（`code` 另补 `display:block`）→ 长代码行横向滚动。**不做全局 display**，避免正文文字重叠 |
| P1 | `copyProps` → `TABLE_TAGS` | `border-collapse` 从全局白名单移到**仅 `<table>`** 输出（它是可继承属性，不限定会连带刷到 `thead/tbody/tr/th/td` 共 17 处）；`NOOP_RULES` 加 `border-collapse: separate` 丢弃 |
| P2 | `PAD_TAGS` / `LH_TAGS` | 对 `blockquote` / `pre` / `code` **定向**补 `padding`；对 `blockquote` / `pre` 补 `line-height`。`margin` 仍全局排除（不动正文间距） |
| P3 | `LIST_TAGS` / `BORDER_DIRS` | `list-style-type` 改为**仅 `ul/ol/li`** 输出；`border-left/top/right/bottom` 改为**与 `border` 简写不同才输出** |

### 8.4 说明：`pre>code` 的 `padding:2.8px 5.6px`

修复后 `pre>code` 上出现了 `padding:2.8px 5.6px`。经查**不是**本轮引入 ——
它是 **Chromium 对 `<code>` 的 UA 默认值**（`0.2em 0.4em`，字号 14px）。
主题 `#wenyan pre code` 未声明 padding，故默认值生效；**预览与导出因此保持一致**
（修复前导出把它剔掉了，反而与预览不符）。如需去掉，可在主题里显式写 `#wenyan pre code { padding: 0 }`。
