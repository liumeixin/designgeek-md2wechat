# WeDraft 借鉴评估（2026-11-02）

> 对象：[pafa/WeDraft](https://github.com/pafa/WeDraft)（MIT，小哈公社出品，7 模板 · 网页/CLI/MCP/Skill 共用渲染核心）
> 目的：判断哪些模板与设计思路值得搬到 `designgeek-md2wechat`。
> 方法：读源码（`templates/`、`packages/wechat-renderer`、`packages/validation`、`packages/shared-types`）＋
> 本地 Chromium 真实跑导出＋`scripts/check_wechat_spec.py` 复检。
>
> **状态：第一档 + 第二档已落地**（2026-11-02 当日完成，见 §七）。第三档未启动。

---

## 一、一句话结论

**它和我们是同类工具，但架构相反。** 值得搬的不是「7 套配色」（我们 19 套不缺），
而是 **① 语义槽位化的模板模型**、**② 表格三件套**、**③ 内容层槽位（图注/说明段/章节编号/参考来源）**。

顺带用它的模板当标尺量了一下自己，发现**我们导出管线丢了 `margin`、`width`、单元格 `padding`**
—— 这三样正是它模板设计的骨架。

---

## 二、架构对比

| | DesignGeek Editor（我们） | WeDraft |
|---|---|---|
| 模板形态 | 一段 `#wenyan xxx { }` 的 CSS 字符串 | **27 个语义槽位 → CSS 声明表**（JSON / TS） |
| 渲染 | Markdown → HTML → 浏览器套 CSS | Markdown → **AST** → 按槽位拼内联 style |
| 导出 | `getComputedStyle` **反推** → 白名单过滤 | 渲染时**已经**是内联 style → 只做 sanitize |
| 依赖浏览器 | **是**（导出必须跑在 Chromium 里） | 否（Node 里就能出） |
| 主题数量 | 19（配色很足） | 7（配色克制，结构完整） |
| 缺口发现 | 靠肉眼看预览 | **schema 强制**：少写一个槽位直接 parse 失败 |

> 关键差别：我们是「先排版、再猜哪些样式该带出去」，它是「先定槽位、渲染时精确写入」。
> 这解释了为什么 10-12 那次会漏掉 `padding`/`overflow`/`width` —— 我们是**减法**，漏一个就少一个；
> 它是**加法**，写什么出什么。

## 三、实测：我们的导出丢了什么

拿 WeDraft 的「蓝图」模板转成我们的 CSS 格式，跑真实导出（`scripts/_out/wedraft-blueprint.html`）：

| 元素 | 预览计算值 | 导出内联 | 结论 |
|---|---|---|---|
| `<p>` | `margin-bottom: 22px` | **无 margin** | 段落节奏全丢 |
| `<h2>` | `margin-bottom: 20px` | **无 margin** | 标题与正文粘连 |
| `<hr>` | `width: calc(100% - 16px)` / `margin: 32px auto 16px` | **无 width、无 margin** | 分隔线变成通栏细线 |
| `<table>` | `width:100%; table-layout:fixed` | **都没有** | 表格按内容自适应，列宽不可控 |
| `<td>` / `<th>` | `padding: 10px 8px` | **无 padding** | 单元格文字贴边 |
| `<img>` | `width: calc(100% - 16px)` | **无 width** | 左右留白丢失 |

导出文件里 `margin` 出现 **0 次**、`width:` 出现 **0 次**、`padding` 只剩 4 次（全部来自
10-12 给 blockquote/pre/code 加的定向规则）。

**根因**：`frontend/index.html` 的 `copyProps` 白名单全局排除 `margin`，且只对
`blockquote/pre/code` 给了 `padding`、只对 `code` 上下文给了 `display/overflow`。
**表格上下文从来没有专属规则** —— 这是我们上一轮复核没查到的盲区。

## 四、27 个槽位对照

WeDraft 的 `layoutTemplateSchema` 定义了 27 个必填/可选槽位。对照我们的现状：

| WeDraft 槽位 | 我们的选择器 | 现状 |
|---|---|---|
| `article` | `#wenyan` | ✅ 已覆盖 |
| `body` | `#wenyan p` | ✅ |
| `heading2` / `heading3` | `#wenyan h2` / `h3` | ✅ 19/19 |
| `quote` | `#wenyan blockquote` | ✅ 19/19 |
| `quoteStrong` | `#wenyan blockquote strong` | ✅ |
| `list` / `listItem` | `#wenyan ul,ol` / `li` | ✅ |
| `code` | `#wenyan pre` | ✅ |
| `image` | `#wenyan img` | ✅（但导出丢 width） |
| `link` / `strong` / `divider` | `a` / `strong` / `hr` | ✅ |
| `table` / `tableHeaderCell` / `tableCell` | `table` / `th` / `td` | ✅ 19/19（但导出丢 width/padding） |
| `tableAltCell` | `tr:nth-child(2n) td` | ✅ 18/19 |
| `note` | `.note` | ⚠️ **1/19**（仅 ugreen 有 `.footnote`） |
| `caption` | `figcaption` / `.caption` | ❌ **0/19，完全没有** |
| `references` / `referenceTitle` / `referenceItem` / `referenceNumber` | `.references …` | ❌ 无结构化区块 |
| `headingNumber` / `headingText` / `heading2Numbered` | `h2 .sec-num` / `.sec-text` | ❌ 无章节自动编号 |
| `quoteMark` | `blockquote .quote-mark` | ❌ 无引号装饰 |
| `tableWrapper` | `.table-wrap` | ❌ 表格无外层容器 |

**结论**：**结构槽位缺 9 个**，集中在「内容层」（图注/说明/编号/参考来源）与「表格容器」。

## 五、值得搬的 13 条（按性价比排序）

### 第一档 · 低成本，只动 CSS 与白名单（建议先做）

| # | 内容 | 具体做法 |
|---|---|---|
| 1 | **表格三件套** | `table`：`width:100%` + `table-layout:fixed` + `border-collapse:separate` + `border-spacing:0`；`th/td`：`padding:10px 8px` + `overflow-wrap:anywhere` + 只留 `border-bottom`；末列 `border-right:0`。**需先在 `copyProps` 给 table 上下文补 `width`/`table-layout`/`padding`** |
| 2 | **斑马纹改用 `tableAltCell`** | 我们现在只有 18/19 主题有 `nth-child(2n)`，且只改背景色。WeDraft 的写法是「奇偶行各一套完整声明」，更稳 |
| 3 | **图片宽度 `calc(100% - 16px)`** | 天然避开规范 §1.4 的固定宽度；比 `100%` 多一层左右呼吸感 |
| 4 | **代码块 `white-space: pre-wrap` + `word-break: break-word`** | 我们 10-12 选了「横向滚动」（`overflow-x:auto`）。两者可取其一，但**`pre-wrap` 在手机端更稳**——公众号端 `overflow-x` 未必生效，`pre-wrap` 是纯 CSS 换行 |
| 5 | **引用悬挂缩进** | `padding-left:24px` + `text-indent:-16px`：首行引号悬挂，续行与正文左缘对齐。视觉细节，几乎零成本 |

### 第二档 · 需改渲染器（价值最高，但要动 `markdown_parser`）

| # | 内容 | 说明 |
|---|---|---|
| 6 | **图注 `caption`** | `![图](url)` 下面紧邻的一行斜体/小字识别为图注，输出 `<figcaption>`。我们 **0/19 覆盖**，是最大空白 |
| 7 | **说明段 `note`** | 靠段首正则 `^(注|说明|参考|来源|资料来源|数据来源|作者|编辑)[：:]` 自动切到更小的灰色样式。**对科技文极有用**（我们文章里「来源：」很常见） |
| 8 | **章节自动编号** | `##` 前缀 `1.` 剥掉，补零成 `01`，用 `headingNumber` 槽位渲染成装饰数字。WeDraft 的实现是在 **AST 节点层剥离**，不破坏加粗/链接 |
| 9 | **参考来源区块** | `## 参考来源` 之后的行自动成 `references`，悬挂缩进 + 自动编号 + 独立标题样式。比现在的裸列表好看得多 |
| 10 | **`tableWrapper`** | 表格外包一层 `<section>`，承载圆角、顶部粗线、`overflow:hidden`。注意：**`overflow` 我们的白名单不带**，需同步放开 |
| 11 | **输出侧 `sanitizeWechatHtml`** | 它是**标签+属性+协议**三层白名单，逐个属性挂正则 `(?!.*(?:expression\|javascript\|url\s*\())`，非 `http(s)` 的 `href` 置空、`localhost` 的 `src` 置空。我们目前只过滤**属性**，不过滤**标签**——这正是 10-12 那次裸 data-URI 能漏出去的原因 |

### 第三档 · 工程能力（对我们工作流价值高，但成本大）

| # | 内容 | 说明 |
|---|---|---|
| 12 | **复制前阻断式检查** | 它的 `ContentIssue` 模型：`level: blocking / warning / info` + `blockIndex` 定位到具体段落；**只有 blocking 拦截复制**。我们的 `check_wechat_spec.py` 是离线脚本，跑完还得自己看。改成 UI 内前置闸门更实用 |
| 13 | **CLI / MCP 接入** | 三端共用渲染核心，AI 一句话就能出排版预览。对我们的 `designgeek-article` 技能链价值最大——写完稿直接调排版，不用手动开网页 |

## 六、不建议搬的

1. **不要为搬模板去搬架构。** 它是 pnpm monorepo（TS + Rust/Tauri），我们是 Python Flask + 单文件 HTML。AST 渲染重构的收益是「导出不依赖浏览器」，但成本是重写整个 `copyHtml()` + 引入 markdown AST 解析器。**除非要做 CLI/MCP，否则不划算。**
2. **`font-family` 一律剥掉。** 它的模板几乎每个槽位都写 `font-family`，而公众号规范 §3 建议不写（微信自有一套字体栈）。照搬会制造 19+ 条 §3 告警。**只有 `code`/`pre` 保留**。
3. **`margin` 不要照抄 8px 边距。** 它的 `margin: 0 8px 24px` 是为「网页预览容器有内边距」设计的；公众号正文区本身有边距，再叠 8px 会偏窄。
4. **两套品牌色模板（小哈公社 / 小哈公社New）跳过。** 橙色系品牌味太重，且我们的 `ugreen` 已是绿系主推。
5. **`font-weight: 750`**（next-edition 用的）在公众号端不一定支持，改用 700。

## 七、已落地的改造（2026-11-02 当日完成）

用户拍板：**margin 全部放行** ＋ **一档 + 二档全做**。

### 7.1 导出管线（`frontend/index.html` · `copyHtml()`）

| 改动 | 前 | 后 |
|---|---|---|
| `margin` | 全局排除（导出 0 处） | **四个方向全量内联**（全零丢弃，`0px auto` 保留） |
| `padding` | 仅 `blockquote`/`pre`/`code` | **全局放行**（全零丢弃）—— 修掉表格单元格贴边、悬挂缩进左移出框 |
| `text-indent` | 无 | 全局放行，**行内元素跳过**（只对块级容器生效） |
| `<table>` | 只有 `border-collapse` | 加 `border-spacing` / `table-layout` / **`width:100%`**（写意图值，不用 computed px） |
| `<img>` | 无 | `max-width: calc(100% - 左右外边距)` + `display:block` —— 把主题的 `calc(100% - 16px)` 意图保下来，且不构成固定宽度 |
| `.table-wrap` | 无 | `overflow:hidden`（圆角裁切） |

> 🔑 关键约束：`getComputedStyle().width` 返回**已解析的 px 使用值**，内联进公众号就是固定宽度（§1.4 禁止）。
> 所以 table 写 `100%`、img 写 `calc(100% - Npx)`，**绝不复制 computed width**。

### 7.2 语义槽位（新增 `enhanceWechatHtml()`）

`marked` 不产出这些结构，主题写了选择器也永远不生效，所以在预览 DOM 上补一层：

| 槽位 | 触发条件 | 产出 |
|---|---|---|
| 表格容器 | 任意 `<table>` | `<section class="table-wrap">` |
| 图注 | 图片后紧跟一段，以「图：/来源：/图片来源：」开头，或整段只有一个 `<em>` | `<figcaption class="caption">` |
| 说明段 | 段首 `注：/说明：/来源：/作者：/编辑：` 等 | `<p class="note">` |
| 章节编号 | `<h2>` 原本带 `1.`/`1、`/`1．` 前缀（**不凭空加编号**） | `.sec-num` + `.sec-text` + `.is-numbered` |
| 参考来源 | `<h2>` 为「参考来源/参考资料/参考文献/References」且紧邻列表 | `.references` + `.ref-title` + `.ref-num` |

### 7.3 出口清洗（新增 `sanitizeWechatHtml()`）

标签白名单 + 属性白名单 + 协议白名单。危险标签整棵删除，`on*` 属性移除，
`javascript:`/`vbscript:`/`data:text/html` 的 `href`/`src` 置空。
**补上「只过滤属性、完全不过滤标签」的缺口。**

### 7.4 五套主题入库

`backend/static/css/themes/wedraft-*.css`（5 个），主题总数 19 → **24**。

转换器：`D:/aiwork/scripts/_out/wedraft2theme.py`（源：`templates/reading-editions.ts`，MIT）。
转换时做的三处适配：
1. `font-family` 除 `code`/`pre` 外**全剥**（公众号规范 §3）
2. 编号列的 `width`/`display:inline-block` **换成 `margin-right:6px`** —— 定宽内联不出去，
   而补零后编号天然等宽，定宽本来就是多余的
3. `heading2Numbered` 的悬挂缩进**弃用**（它是给定宽编号列做补偿的，已不需要）
