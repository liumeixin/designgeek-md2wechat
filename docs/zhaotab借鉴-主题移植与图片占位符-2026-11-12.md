## 二、对方的主题模型

zhaotab 的 35 套主题不是 CSS 文件，而是一段 JS 数据：

```js
C({ id: "orange", name: "橙心", accent: "#ef7060", tags: [...], font: ...,
    page: {...}, code: "dark",
    styles: { h2: "...", blockquote: "...", ... },      // 覆盖项
    decor:  { h2: (e, t) => `<span style="...">${e}</span>`, hr: ... } })
```

关键在工厂函数 `C()`：

| 机制 | 说明 | 我们的对应做法 |
|---|---|---|
| 基样式表 `g` | 30 个槽位（`wrapper/p/h1..h4/strong/em/del/sup/sub/link/blockquote/blockquoteP/ul/ol/li/code/pre/preBar/preCode/hr/tableWrap/table/th/td/fnRef/footnotes/fnTitle/fnItem/imgSlot`）的默认值 | 直接译成 `#wenyan xxx { }` 的默认声明 |
| `styles` | 按槽位覆盖基样式，值是**内联 CSS 字符串**，含 `${pe(n,.06)}`（= `rgba(...)`）、`${r}/${ue}/${re}/${K}`（字体栈）、`${n}`（accent）、`${d}`（暗色判断） | 模板变量展开成真实值后写进 CSS |
| `decor` | 按槽位给**返回 HTML 的函数**，如 `h2: e => \`<span style="...">${e}</span>\`` | ⚠️ 分水岭：**能用 CSS 表达的就搬，必须插 DOM 的就只能放弃** |

装饰的具体形态只有 7 种：`h1 / h2 / h3 / hr / quoteMark / ulMark / olMark / card`。
`h2:(e,t)=>` 拿的是 `(文本, 序号)`，配套有 `ge()`（两位补零）、`Je()`（壹贰叁…）、`H()`（字符+两侧横线）、`$e()`（彩色数字胶囊）等辅助函数 —— 这些全部依赖"往标题里插 span"。

## 三、移植结果：哪些搬到了，哪些没搬到

### 3.1 已实现（纯 CSS，导出后仍然成立）

| 原装饰 | 我们的实现 | 效果 |
|---|---|---|
| 胶囊 / 实心块 h2 | `#wenyan h2 { display:table; margin:X auto Y; padding; background; border-radius; box-shadow }` | 橙心、朱印等主题的彩色药丸标题 |
| 标题前缀字形 | `#wenyan h3::before { content:"●"; color; margin-right; vertical-align }` | 小圆点 / 小方块 / 序号字形 |
| h1 包裹型装饰 | `#wenyan h1::before / ::after { content:"『" / "』" }` | 朱印主题的六角括号 |
| h2 下划线 / 左侧竖线 | `border-bottom` / `border-left` | 简约、报纸类 |
| 代码块 / 表格 / 引用 / 列表 | 逐槽位声明 | 全部 |

`::before` / `::after` 能被导出保留，是因为 `copyHtml()` 里的 `injectPseudoElements()` 会把 CSS 的 `content` **实体化成真实 `<span class="pseudo-before">`** —— 这也是这套移植能成立的前提。

### 3.2 未实现（需改渲染器，本轮不做）

| 未移植项 | 为什么 |
|---|---|
| h2 编号徽章（壹/贰/叁、01/02） | 要往标题里插 `<span>` 并做序号计数，纯 CSS `counter` 在导出后不生效 |
| 卡片容器（`card`） | 要把整节内容包进一个带背景的外层 `<div>`，渲染器不产生这层结构 |

| 无序 / 有序列表符号（`ulMark` / `olMark`） | 需要 `li` 内部额外 span；`list-style-image` 导出后被平台覆盖 |
| 字符分割线（`hr`） | 原实现是"一排 ❖ / · · ·"的文本节点；`<hr>` 是空元素，塞不进子节点 |

**每套主题的 `未移植` 清单都写在该 CSS 文件头注释里**，不是笼统一句"部分未移植"。例如：

## 四、图片占位符（本轮借鉴的重点功能）

### 4.1 原实现

zhaotab 在渲染阶段把 `<img>` 换成一个 `<span data-img>`：

```
📷 在这里插入图片：${alt}
粘贴到公众号后，用编辑器的「图片」按钮插入，再删掉这个框
```

样式：`border:1px dashed`、`background:#fafafa`、`color:#999`、居中、`padding:22px 12px`。

**它解决的问题**：公众号不保留外链图。带 `https://example.com/x.png` 的稿子粘进去，图会裂成红叉，事后很难定位"这里原本该有张图"。

### 4.2 我们的实现（`frontend/index.html`）

| 点 | 做法 |
|---|---|
| 默认关闭 | `let imgSlotOn = false` —— 不打开就完全走原有逻辑，24 套老主题输出**逐字节不变** |
| 入口 | 顶栏新增按钮 `#imgSlotBtn`（标题「图片占位符」），激活态复用既有 `.btn.active` |
| 持久化 | `state.imgSlot` 存 localStorage，刷新后保持 |
| 替换时机 | 在 `enhanceWechatHtml()` **第 ⑥ 步**（图注识别之后），所以图注仍能正确挂到 caption 上 |
| 跳过微信图床 | `WX_IMG_HOST = /^https?:\/\/(?:mmbiz\.qpic\.cn|mmbiz\.qlogo\.cn)\//i` —— 已经是微信图床的图不该换 |
| 文本安全 | 用 `createTextNode` 拼 `alt`，`alt` 里含 `<` / `&` 也不会破标签 |
| 导出保留 | `copyHtml()` 里对 `.img-slot` 补 `display:block`，否则上下 `margin` 不生效（行内元素不吃纵向 margin） |

生成的 DOM：

```html
<span class="img-slot">📷 在这里插入图片：封面图<br>粘贴到公众号后，用编辑器的「图片」按钮插入，再删掉这个框</span>
```

### 4.3 与主题的关系

`index.html` 里给 `#wenyan .img-slot` 加了一份**兜底样式**（虚线灰框）。35 套 `zt-*` 主题各自又带一份 `imgSlot` 槽位（来自 zhaotab 的基样式表，色调随主题 accent 走）。所以：

- 老主题（24 套）→ 用 `index.html` 的兜底灰框；
- `zt-*` 主题（35 套）→ 用各自主题色虚线框。

## 五、踩到的坑（都跟本项目既有陷阱重合）

### 5.1 🔴 `themes.json` 双源陷阱二次复发

`build.py` 原来按「**新的比旧的短就保留旧的**」决定 `themes.json` 用哪份：

```python
if name in CSS_AUTHORITATIVE:      # 只有 4 个主题走白名单
    continue
if len(new_css) <= len(old_css):   # ← 长度启发式
    keep old
```

结果：我把 `zt-terminal` 的 `h3::before { content: "&gt;" }` 修成 `">"` 后，因为**修完变短了**，旧条目又被静默塞回去，导出里仍是 `&amp;gt;`。

修法是把 `zt-` 整段前缀加进"以 CSS 为准"名单：

```python
CSS_PREFIX_AUTHORITATIVE = ("wedraft-", "zt-")
if name in CSS_AUTHORITATIVE or name.startswith(CSS_PREFIX_AUTHORITATIVE):
    continue
```

修完复核：35/35 与 CSS 源文件**逐字节一致**。

### 5.2 伪元素里不能写 HTML 实体

`injectPseudoElements()` 把 `content` 的值**原样当文本**塞进 span，不做 HTML 解码。所以 CSS 里写 `content: "&gt;"` 会先被序列化成 `&amp;gt;`，导出后微信里显示成 `&gt;` 而不是 `>`。

**结论：主题 CSS 的 `content` 一律写真实字符。**

### 5.3 `getComputedStyle` 的 `margin: auto` 陷阱

胶囊标题靠 `display:table + margin:X auto Y` 居中。但 `getComputedStyle().marginLeft` 返回的是**已解析的 px 使用值**（实测 `27.75px`），一旦内联进去，换屏宽就不居中了。

`copyHtml()` 里因此做了两件事：

```js
// 1) 对 h1~h6 且 display:table/inline-block 的，横向 margin 强制写 auto
s += 'margin:' + mt + 'px auto ' + mb + 'px;';
// 2) copyProps 主循环里跳过 margin，避免同一属性输出两遍
if (prop === 'margin' && headingAutoMargin) continue;
```

## 七、导出 = 预览：容器级排版下沉（同日补做）

移植完成后发现一个**贯穿全部 59 套主题**的老问题：导出外层 `<section>` 硬编码
`line-height:1.75; font-size:17px`，把主题自己在 `#wenyan` 上声明的字号盖掉了。

而 `copyProps` 的白名单里**没有 `line-height`**（只对 `blockquote` / `pre` 定向内联），
所以标题、表格单元格、正文段落全都靠**继承**外层容器 —— 容器写 17px/1.75，主题写什么都被无视。

### 7.1 修法一：容器声明改为「主题优先」

```js
const containerProps = [ ...背景类..., 'color', 'padding',
                         'font-size', 'line-height', 'letter-spacing', 'text-align', 'word-break'];
// 主题没声明字号 / 行高时才补 17px / 1.75，避免同一属性出现两遍
for (const [k, v] of Object.entries({ 'font-size': '17px', 'line-height': '1.75' }))
  if (!decls[k]) decls[k] = v;
```

结果：59/59 主题的容器字号/行高与主题声明**完全一致**（`zt-*` 15px/1.8、`wedraft-*` 16px/1.84、
`ugreen` 16px/2、`default` 17px/1.75）。

### 7.2 修法二：补回被丢掉的 `line-height`

容器统一后，正文段落（`p` / `li`）跟着容器走，问题解决；但**标题和表格单元格**仍不对 ——
它们各自的主题行高（`#wenyan h1 { line-height:1.5 }`、`#wenyan th { line-height:1.6 }`）
在导出后没有任何载体。于是把 `LH_TAGS` 从 `{blockquote, pre}` 扩到：

```
blockquote, pre, h1~h6, th, td, li
```

另外两处定向补：

- `<blockquote>` 内的 `<p>`：引用块已内联自己的行高，不补的话 `<p>` 会继承引用块的值
- `<pre>` 内的 `<code>`：代码块内层 `<code>` 常被主题单独设行高（如 1.6）

**为什么可以内联 px 行高**：`line-height` 不属于 §1.4 的「固定尺寸」（那是 width/height 的事），
而 §1.3 只要求 `line-height` 不小于字号，主题自身均满足。且导出的 `font-size` 本来就是 px，
两者单位一致，不会出现「字号随平台缩放、行高不跟」的错位。

### 7.3 实测：预览 vs 导出 计算样式对比

方法：同一篇样稿，先在编辑器里渲染并采集 `p/h1/h2/h3/blockquote p/th/td/li/code/pre code/strong`
的 `fontSize / lineHeight / color / letterSpacing / textAlign`；再把导出的 HTML 载入空白页采集同名
选择器，逐项 diff。6 套代表性主题（zt-orange / ugreen / default / claude / wedraft-blueprint / dark-green）：

| 阶段 | 不一致项 | 说明 |
|---|---|---|
| 改动前（17px 硬编码） | **84** | 字号、行高、对齐全线偏移 |
| 只下沉容器声明 | **54** | `font-size` 归零差异，`text-align` 大量修复 |
| 再扩 `LH_TAGS` | **33** | 标题 / 表格行高修复 |
| 再补 blockquote-p / li | **30** | 仅剩 29 条 `start` vs `left`（LTR 下等价）+ 1 条代码块 `letter-spacing` |

即：**实质差异从 84 降到 1**。体积代价约 **+350~390 字节/篇**（约 +3.6%）。

> 注：上表是 6 套抽样。后来把对比扩到**全部 59 套**，才发现下面 3 个更深的问题。

### 7.4 `background-image` 的 `data:` URI 被分号截断（老 bug）

容器属性原先用正则 `[^;}]+` 取值。而主题里的背景图长这样：

```css
background-image: url("data:image/svg+xml;utf8,<svg …>"), url("data:image/svg+xml;…");
```

`[^;}]+` 会在 `svg+xml;` 的**分号处**截断，于是在 style 属性里留下一个**未闭合的 `url("data:…`**。
CSS 解析器接着把整条声明块（含 `font-size` / `line-height`）当成一个未结束的字符串吞掉 ——
`color-pop`、`fireworks` 两套主题导出后正文行高直接退化成 `normal`。

修法：换成「引号 + 括号感知」的扫描器 `readRuleBody()` / `readDecl()`，不再用正则。
顺带把值里的 CSS 注释和多行排版压掉（data URI 常带 `/* 五角星大小 */` 这类注释）。

### 7.5 `line-height` 必须写无单位比例，不能写 px

第一版把 `computed.lineHeight`（px）直接内联，结果 59 套主题的 `code` 行高全部对不上：

- 预览：`<p>` 是 `line-height:1.8`（无单位），内层 `<code>` 字号 13.5px → **24.3px**
- 导出：`<p>` 内联了 `line-height:27px`（绝对值），`<code>` 继承 27px → **27px**

根因是 `line-height` **可继承且无单位时会按自身字号重算**，px 则是死的。
所以改成 `lhValue()`：`computed 行高 ÷ computed 字号` → 输出 `1.8` 这样的比例。
主题里 581 处 `line-height` 声明只有 1 处用 px（color-pop 的圆形徽章），换算后渲染完全一致。

### 7.6 `content: counter(…)` 被当文字印出来（老 bug）

`injectPseudoElements()` 从 CSSOM 取 `content` 的值当文本用。但 CSSOM **不解析** `counter()`，
`content: counter(pop-counter)` 取回来就是字面量 `counter(pop-counter)`，于是正文里印出
「counter(pop-counter)有序列表第一项」。

影响 10 套主题（cli / color-pop / fireworks / girl-pink / grass / lavender-purple / macarons /
newyear / sunrise / winter）—— 正好是「编号徽章」那一类。

修法：微信里 CSS 计数器本来也不生效，所以退化成**父容器内的序号**（1、2、3…），
`attr(x)` 同理替换成元素属性值；解析不掉的表达式宁可留空也不印字面量。
同时把 `counter-increment` / `counter-reset` 从伪元素内联属性里排除（内联出去毫无作用），
空 `style=""` 也不再输出。

| `scripts/export_all.mjs` | 一次启动浏览器，批量导出全部/指定前缀主题。**复用同一页面上下文**，59 套约 1 分钟（逐个重启浏览器要 20 分钟）。产物是 `copyHtml()` 的真实输出（劫持剪贴板捕获），不是预览 DOM。 |
| `scripts/compare_preview_export.mjs` | 逐元素比对「预览计算样式」与「导出计算样式」。按全部匹配元素**逐个**比对（不是只比第一个），元素数不同时报「结构差异」而非样式差异；`start`/`left` 这类渲染等价项单列；有实质差异时退出码 1。 |
| `scripts/_pw.mjs` | 两者共用的 Playwright 加载（`playwright-core` → `playwright` 回退，用 `createRequire` 以支持 `NODE_PATH`）、Chromium 路径探测（`CHROME_PATH` → Playwright 下载目录按版本号取最大 → 系统 Chrome）、页面打开（带一次重试 —— Flask 开发服务器实测会偶发卡满 30s）。 |

用法：

```bash
node scripts/export_all.mjs http://127.0.0.1:18888/ sample.md out/ 1 zt-
node scripts/compare_preview_export.mjs http://127.0.0.1:18888/ sample.md out/
VERBOSE=1 node scripts/compare_preview_export.mjs http://127.0.0.1:18888/ sample.md out/ zt-orange
```

改主题 CSS 或动 `copyHtml()` 之后，标准动作是：
`export_all` → `compare_preview_export`（必须实质差异 0）→ `check_wechat_spec.py`（必须 error 0）。
