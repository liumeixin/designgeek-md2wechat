# 代码块 / 表格「微信原生样式」适配说明

- **日期**：2026-11-19
- **触发**：用户反馈表格与多行代码块复制进公众号后能显示，但过长内容被截断、拖不动；希望复制时自动适配公众号原生的代码块/表格样式。
- **结论**：已实现，工具栏「微信原生样式」开关（默认开）。只改复制产物，不改预览主题。

---

## 一、先纠正一个前提：官方规范里没有「默认样式」

逐条核对微信公众平台编辑器插件开发规范全文，关于这两类元素**只有禁止条款，没有推荐样式**：

| 条款 | 内容 |
|---|---|
| §1.8 `<pre>` | 不许用 `<pre>` 包普通正文（默认 `white-space:pre`，移动端会被截断）；未提 `<code>` |
| §1.4.2 `<table>` | 不许固定列宽（窄屏溢出），仅作为错误示例出现 |
| §1.4.4 | `data-ignore-width` 豁免机制，**明确把「横向滚动容器」列为适用场景** |

所以「公众号默认样式」不是规范定义的东西，而是**编辑器内置组件长那样**——工具栏点「代码块」插入的是 `code-snippet__fix` 那套 DOM。所谓「适配」本质是复刻这个结构，让微信把粘贴内容当原生代码块对待。

两个绕不开的事实：

1. 外部粘贴的普通 `<pre><code>` 不会被微信自动转成代码块组件，必须在复制那一刻就输出原生结构；
2. 语法高亮即使原生结构也要进编辑器后**点一下代码块**才触发，纯粘贴做不到自动上色。

## 二、痛点复现与方案

实测（375px 窄屏 + 超长单行代码 + 8 列宽表）：

| | 代码块 scrollWidth / clientWidth | 表格 scrollWidth / clientWidth | 结果 |
|---|---:|---:|---|
| 改动前 | 373 / 373 | 375 / 375（`overflow:hidden`） | 截断，拖不动 ❌ |
| 开关开 | **1886 / 333** | **900 / 375** | 均可横滑 ✅ |

方案落在 `copyHtml()` 的 `adaptToWechatNative()`（样式内联 + 伪元素注入之后执行）：

- **代码块**：`pre>code` → `section.code-snippet__fix[data-ignore-width]`
  - 左侧 `ul.code-snippet__line-index` 放**真实数字**行号（不用 CSS counter，微信会清洗 counter；实测原实现 10 套主题的 `counter(pop-counter)` 会印在正文上，同坑）
  - 右侧 `pre.code-snippet__js[data-lang]` 带 `overflow-x:auto`，每行一个 `code>span.code-snippet_outer`
- **表格**：`.table-wrap` 加 `overflow-x:auto` + `data-ignore-width`，table 按列数给 `min-width`（上限 900px）
- **配色**：结构换微信原生，颜色/背景/边框从主题已内联的 style 里抽出来带到新节点；行号直接用代码正文色（不用 opacity——§1.1 禁；不用半透明——叠深底会低对比度触发 §4.1.1）

## 三、为什么用 data-ignore-width 而不是硬内联 overflow

规范 §1.4 会检测固定宽度/溢出，`min-width` + `overflow-x:auto` 本来可能被判违规。`data-ignore-width` 是官方为横向滚动容器准备的豁免，加在容器上后节点及整棵子树跳过 width 检测。配套改动：`WX_ALLOWED_ATTRS` 放行 `data-ignore-width` 与 `data-lang`，否则出口清洗会把它们剥掉。

`check_wechat_spec.py` 第 122 行已识别该豁免，无需改自检脚本。

## 五、已知限制

- 语法高亮仍需粘贴后手动点一下代码块（微信机制，非本项目可控）。
- 行号用真实文本，复制出来会随代码一起进文章——这是微信原生代码块的样子，符合预期。
- 「微信原生样式」开关只影响导出；编辑器预览始终显示主题原样（主题保真比对因此要走 `native=0`）。
